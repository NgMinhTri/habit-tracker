## 1. Overview

| Part     | Tech                                                                                           | Path           |
| -------- | ---------------------------------------------------------------------------------------------- | -------------- |
| Frontend | React 19, Vite, TypeScript, Tailwind CSS v4, React Router, TanStack Query, lucide-react        | `src/frontend` |
| Backend  | .NET 10 Minimal API, Clean/layered architecture, EF Core 10 + SQLite                           | `src/backend`  |
| Tests    | Backend: xUnit + NSubstitute. Frontend: Vitest + React Testing Library (jsdom)                  | see below      |

The app is a **mobile-first web app**: UI is designed for ~375px wide screens first (design reference 390 × 844); desktop shows the same narrow column (max 440px) centered.

**Requirements** live in `working-artifacts/` (Product Brief, user stories with AC images, `DESIGN.md`); start from `working-artifacts/DEVELOPER-AGENT-GUIDE.md`. This file defines *how* to build; those documents define *what*.

**Persistence:** the Product Brief's "data is stored on the user's device" is satisfied by the local SQLite database of the API running on the same machine (see §3.6). Domain data is not kept in browser storage.

## 3. Backend Rules

### 3.1 Layer dependencies (strict)

```
Api ──► Application ──► Domain
 │           ▲
 └──► Infrastructure
```

| Layer          | May reference              | Must NOT                                                     |
| -------------- | -------------------------- | ------------------------------------------------------------ |
| Domain         | nothing                    | reference EF Core, ASP.NET, or any other project             |
| Application    | Domain                     | reference Infrastructure, EF Core, ASP.NET, `HttpContext`    |
| Infrastructure | Application (→ Domain)     | contain business rules                                       |
| Api            | Application, Infrastructure| contain business logic or query `DbContext` for feature work |

### 3.2 Where to put what

| You need…                              | Put it in                                                                   |
| -------------------------------------- | --------------------------------------------------------------------------- |
| Entity / value object / domain rule    | `Domain/Entities/<Name>.cs` (inherit `BaseEntity`)                          |
| Use case / service logic               | `Application/Features/<Feature>/<Feature>Service.cs` + `I<Feature>Service`  |
| Request/response DTOs                  | `Application/Features/<Feature>/Dtos/` as `record`                         |
| Repository interface                   | `Application/Features/<Feature>/I<Entity>Repository.cs`                     |
| Repository implementation              | `Infrastructure/Persistence/Repositories/<Entity>Repository.cs`             |
| EF mapping                             | `Infrastructure/Persistence/Configurations/<Entity>Configuration.cs`        |
| HTTP endpoints                         | `Api/Endpoints/<Feature>Endpoints.cs` implementing `IEndpointGroup`         |
| Current time                           | inject `IClock` — never call `DateTime.Now`/`UtcNow` in Domain/Application  |

### 3.3 Conventions

- Namespace = folder path: `HabitTracker4TP.<Layer>.<Folder>` (file-scoped namespaces).
- One public type per file; file name = type name.
- Async methods end with `Async` and accept `CancellationToken`.
- DTOs are `sealed record`. Never return entities from endpoints.
- Endpoints: use `TypedResults`, `.WithName()` and `.WithTags()`; errors are returned as **ProblemDetails** (already wired via `AddProblemDetails()` + `UseExceptionHandler()`). Validation errors follow §3.6.
- Routes are kebab-case, plural nouns, under `/api` (the prefix is added by `MapEndpointGroups`, do not repeat it).
- Register services in the layer's `DependencyInjection.cs`, never in `Program.cs`.
- Warnings are errors (`TreatWarningsAsErrors`) — fix them, don't suppress.
- Package versions are pinned (no `*` versions).

### 3.4 Endpoint template

```csharp
namespace HabitTracker4TP.Api.Endpoints;

public sealed class FooEndpoints : IEndpointGroup
{
    public void MapEndpoints(IEndpointRouteBuilder api)
    {
        var group = api.MapGroup("/foos").WithTags("Foos");
        group.MapGet("/", GetAll).WithName("GetFoos");
    }

    private static async Task<Ok<IReadOnlyList<FooDto>>> GetAll(IFooService service, CancellationToken ct)
        => TypedResults.Ok(await service.GetAllAsync(ct));
}
```

### 3.5 Database / migrations

- Connection string: `ConnectionStrings:Default` in `Api/appsettings.json` (`Data Source=habittracker.db`). `*.db` files are git-ignored.
- No migrations exist yet — the first feature that adds an entity creates `InitialCreate`.
- Create a migration (run from `src/backend`):

```bash
dotnet ef migrations add <Name> \
  -p src/HabitTracker4TP.Infrastructure \
  -s src/HabitTracker4TP.Api \
  -o Persistence/Migrations
```

- Requires the tool: `dotnet tool install --global dotnet-ef`.

### 3.6 API & data contracts

**Validation errors**
- Rules that need no data are Domain invariants; rules that need data (e.g. uniqueness) live in the Application service.
- Expected validation failures are not exceptions across the API boundary. The service reports field errors; the endpoint returns `TypedResults.ValidationProblem(errors)` (HTTP 400) and its signature is `Results<Created<FooDto>, ValidationProblem>` (or `Ok<...>`).
- `errors` keys are the camelCase request field names (`name`, `endDate`); each value holds the exact message from the user story's UI table. A duplicate-name error is a `400` on `name`, not a `409`.
- Unexpected failures throw and become a `500` ProblemDetails automatically.
- The frontend shows `ApiError.problem.errors?.[field]?.[0]` inline at the location the story specifies (§4.2). Client-side checks may mirror the rules for instant feedback but must use identical messages; the server stays authoritative.

**Dates**
- Calendar dates are `DateOnly` in Domain, DTOs, and EF (SQLite stores `TEXT` `yyyy-MM-dd`); JSON carries `"YYYY-MM-DD"`.
- The client decides "today" from the device's local date and sends it (body or `?date=` query). The backend never derives a calendar day from `IClock`; `IClock` is only for timestamps such as `CreatedAt`.

**Case-insensitive unique text** (e.g. habit name)
- Trim before validating and storing.
- Check in the Application service through the repository (case-insensitive comparison) to return the field error.
- Back it in the database: EF configuration `.UseCollation("NOCASE")` on the column plus a unique index.

**Fixed option sets** (e.g. habit color, icon)
- Persist a stable lowercase string key (`"rose"`), never a display value such as a hex color. Validate the key against the allowed set in Domain/Application. The frontend maps keys to DESIGN.md tokens.

**Persistence**
- The local SQLite file (`habittracker.db`) is the on-device store. Data survives app reload and API restart; it is lost only if the file is deleted.

## 4. Frontend Rules

### 4.1 Where to put what

| You need…                                   | Put it in                                                  |
| ------------------------------------------- | ---------------------------------------------------------- |
| New screen / route                          | `pages/<Name>Page.tsx` + register in `app/router.ts`       |
| Full-screen screen without bottom nav (form, picker) | `pages/<Name>Page.tsx` + top-level route **outside** the `AppLayout` children in `app/router.ts` |
| HTTP call to backend                        | `features/<feature>/api/<verbNoun>.ts` using `apiClient`   |
| Data fetching / mutation                    | `features/<feature>/hooks/use<Thing>.ts` (TanStack Query)  |
| Feature-specific component                  | `features/<feature>/components/<Name>.tsx`                 |
| Reusable generic UI (no business knowledge) | `components/ui/<Name>.tsx`                                 |
| App shell (header, nav)                     | `components/layout/`                                       |
| Global provider                             | `app/providers.tsx`                                        |

### 4.2 Conventions

- Components: PascalCase file & named export (`export function Foo()`); **no default exports**.
- Hooks: `useXxx`, one hook per file. Query keys defined next to the hook as `xxxKeys`.
- Never call `fetch` directly — always `apiClient` (`/api` prefix + ProblemDetails → `ApiError`).
- Components never call `apiClient` directly — go through a feature hook.
- Import a feature only via its `index.ts` from outside the feature.
- Server state lives in TanStack Query; don't copy it into `useState`. Prefer derived values over `useEffect` + `setState`.
- Styling: Tailwind utility classes only; no CSS modules / inline styles (except dynamic values).
- Design tokens: every color, font, radius, shadow, and type size comes from `working-artifacts/design-system/habit-tracker/DESIGN.md` via the `@theme` tokens in `index.css` (e.g. `bg-ink`, `text-muted`, `bg-habit-rose`, `ring-habit-rose-ring`, `rounded-card`, `shadow-panel`, `text-card-title`, `max-w-app`, `bg-app`). Don't use Tailwind palette colors (`slate`, `indigo`, ...) or hex literals in components. Add a missing DESIGN.md token to `@theme` instead of inventing one. Spacing uses the default scale (DESIGN s1–s6 = `1`, `2`, `3`, `4`, `6`, `8`).
- Field errors from the API: read `ApiError.problem.errors[field][0]` (§3.6) and render it in the story's error block.
- Local dates: build `YYYY-MM-DD` from local date parts; never `toISOString().slice(0, 10)` (UTC shift).
- Icons: `lucide-react`, decorative icons get `aria-hidden="true"`.
- Formatting: Prettier (`npm run format`); lint must pass (`npm run lint`).

### 4.3 Mobile-first UI rules (mandatory)

1. Write base classes for mobile; add `md:`/`lg:` only for larger screens.
2. App content stays within the `max-w-app` (440px) column — `AppLayout` for tabbed screens, the same column classes for full-screen routes. Don't build separate desktop layouts.
3. Touch targets ≥ **44×44px** (`min-h-11`/`size-11` or larger).
4. Inputs/selects/textareas font-size ≥ **16px** (prevents iOS zoom; enforced in `index.css`).
5. Respect safe areas: use `pt-safe` / `pb-safe` utilities for anything fixed to screen edges.
6. Use `min-h-dvh` (not `h-screen`). Fixed bottom elements must not cover content (main has bottom padding for `BottomNav`).
7. Use `active:` states for touch feedback; don't rely on `hover:`.
8. Always render loading (skeleton) and empty/error states.
9. Screen flow follows the user story and mockup (e.g. a full-screen New Habit form). Only when no story/mockup defines it, default to a floating action button + bottom sheet.
10. Dates sent to the API use the device's local date (`YYYY-MM-DD`).

### 4.4 Dev server

- `vite.config.ts` proxies `/api` → `http://localhost:5171` (override with env `VITE_API_TARGET`). Frontend code always uses relative `/api/...` URLs.
- `server.host: true` exposes the dev server on LAN for testing on a real phone.

## 5. Testing Conventions

### Backend (xUnit + NSubstitute)

- Test project mirrors the source project folders: `Application/Features/Foo/FooService.cs` → `Application.Tests/Features/Foo/FooServiceTests.cs`.
- Test name: `Method_State_ExpectedResult` (e.g. `Create_EmptyName_Throws`).
- Arrange / Act / Assert separated by blank lines; built-in `Assert` only.
- Mock interfaces (repositories, `IClock`) with `Substitute.For<T>()`; never hit the real database in unit tests.
- Tests that cover a story AC carry a trait: `[Trait("AC", "US01-AC3")]` (filter with `dotnet test --filter AC=US01-AC3`).

### Frontend (Vitest + React Testing Library)

- Test file next to the file under test: `Foo.tsx` → `Foo.test.tsx`.
- Render with `renderWithProviders()` from `src/test/utils.tsx` (QueryClient + router).
- Mock the network with `vi.stubGlobal('fetch', ...)` + `mockFetchResponse()`; globals are auto-restored.
- Query by role/label/text (`getByRole`, `findByRole`) — avoid test IDs and class names.
- Import `describe/it/expect/vi` from `vitest` explicitly (globals are off).
- Tests that cover a story AC start their name with the story and AC: `it('US01-AC3 rejects an empty name', ...)`. Assert exact message text from the UI table.

## 6. Recipe: Adding a New Feature (`Foo`)

**Backend**
1. `Domain/Entities/Foo.cs` (inherits `BaseEntity`, validates its own invariants) + tests in `Domain.Tests/Entities/FooTests.cs`.
2. `Application/Features/Foo/`: `IFooRepository.cs`, `IFooService.cs`, `FooService.cs`, `Dtos/*.cs`; register in `Application/DependencyInjection.cs`.
3. `Infrastructure/Persistence/Configurations/FooConfiguration.cs`, `Repositories/FooRepository.cs`, add `DbSet<Foo>` to `AppDbContext`; register in `Infrastructure/DependencyInjection.cs`.
4. `Api/Endpoints/FooEndpoints.cs` implementing `IEndpointGroup` (auto-mapped). Add requests to `HabitTracker4TP.Api.http`.
5. Create migration (§3.5).
6. Tests: `Application.Tests/Features/Foo/FooServiceTests.cs`.

**Frontend**
1. `features/foo/api/*.ts` — types + functions using `apiClient`.
2. `features/foo/hooks/useFoos.ts`, `useCreateFoo.ts` — TanStack Query; invalidate `fooKeys` on mutation.
3. `features/foo/components/*.tsx` + `*.test.tsx`.
4. `features/foo/index.ts` — export public pieces.
5. `pages/FooPage.tsx` + route in `app/router.ts` (+ tab in `BottomNav` if top-level).

**Done when**: `dotnet build` (0 warnings), `dotnet test`, `npm run lint`, `npm run test:run`, `npm run build` all pass. For story work, also: every AC has a passing test tagged with its ID (§5) or a recorded manual check, and each screen was compared with its `ACn-*.png` at 390px.

## 8. Don'ts

- ❌ Business logic in endpoints, `Program.cs`, pages, or `components/ui`.
- ❌ `Application` referencing `Infrastructure` or EF Core.
- ❌ `fetch()` outside `lib/apiClient.ts`; `apiClient` calls inside components.
- ❌ Default exports in frontend source files.
- ❌ Desktop-first styles, hover-only interactions, touch targets < 44px.
- ❌ `DateTime.Now` / `UtcNow` in Domain/Application (use `IClock`).
- ❌ Floating package versions, committing `*.db` files, hand-editing migrations.
- ❌ Tailwind palette colors or hex literals in components instead of DESIGN.md tokens.
- ❌ Paraphrasing user-story messages or labels.
