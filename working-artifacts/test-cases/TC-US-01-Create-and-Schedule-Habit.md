## Assumptions and Open Questions

- **A1 (test clock):** Cases use dates relative to "today" (T). Example values assume T = Sat 2026-10-17 (week Mon Oct 12 – Sun Oct 18). Automation should fix the browser clock for determinism.
- **A2 (schedule check):** Scheduling is verified through the Today screen week strip and week arrows (US-02), because US-01 has no other view of a habit's schedule.
- **A3 (test isolation):** Each case starts from cleared app storage in a fresh browser profile unless the preconditions state existing habits. Existing habits are created through the New Habit screen or a test fixture.
- **Q1:** The name field accepts at most 41 characters. Should a name with surrounding spaces whose trimmed length is ≤ 40 but raw length > 41 be accepted? The 41-character input cap would currently truncate it before trimming. TC_HABIT_018 covers only the 41-raw-character case.
- **Q2:** How are characters counted for emoji or combined Unicode characters (code units vs. visible characters)? Not covered until confirmed.
- **Q3:** The icon source is a developer decision; TC_HABIT_030 checks "all icons from the source" against the source list chosen by the team.
- **Q4 (from story):** Persistence after browser data is cleared, or on another browser/device, is not defined; not covered.
- **Q5 (from story):** Close always discards without a confirmation prompt; cases follow the story as written, pending product owner confirmation.
- **Q6:** Behavior when the user enters an invalid end date and then turns "Set end date" off and saves is not stated; not covered.
- **Q7:** TC_HABIT_017 assumes typing 42 characters keeps only the first 41. The story states only that the field "accepts up to 41 characters"; typing versus pasting is not specified.
- **Q8:** TC_HABIT_035 assumes the form shows its default values after Close and reopen. The story states only that entered values are discarded.
- **Q9:** When both the name and the end date are invalid, which error is shown, or are both? No rule exists; not covered.
- **A4 (icon references):** Icons are referenced by the mockup's sample emoji. If the chosen icon source differs, use the icon at the same grid position (1 = 🧘 ... 40 = 🎯).
- **A5 (automation):** Default `Yes` means the case is deterministic with a fixed browser clock (A1), a fresh browser context (A3), and the native date input filled programmatically. Cases that cannot meet this are `No`.
- **A6 (schedule controls):** There is no "Do it once" option, toggle, or schedule-type selector. The only schedule control is the Repeat switch (default off). With Repeat off, the schedule card shows one row labeled "Do it once" whose date is always Today and cannot be changed (no date picker; this differs from the story's AC1 UI table, which describes an editable chip, so confirm with the product owner). With Repeat on, that row is replaced by Start, Frequency (read-only "Every day"), and a "Set end date" switch (default off). The End row and end date calendar exist only while "Set end date" is on. "One-time" in case titles means Repeat off.
- **A7:** Turning "Set end date" off after choosing an end date means the habit is saved without an end date (repeats indefinitely). This follows from AC2 ("indefinitely when no end date is set"); the story does not state it explicitly (TC_HABIT_044).
- Out of scope per story: editing/deleting habits, recurrence other than one-time/daily, custom icons/colors, icon search/categories, authentication.
